# Decision: the tape master — `build198x tape` masters composed cassettes, starting with the Spectrum

**Status:** Built (2026-11-07, build198x/build198x#60). Placement settled in
Build198x by the umbrella record
[`tape-framing-vs-mastering.md`](../../../decisions/tape-framing-vs-mastering.md).

**Date:** 2026-07-03, when demand fired. Placement resolved 2026-07-08. Design
agreed and consumer replaced 2026-11-07.

## The decision

Build198x masters **composed tapes**: a loader, a loading screen and a program
on one cassette image, in the order the machine's loader reads them. The verb is
`build198x tape --machine <id>`. Tape formats share extensions but nothing else
(a Spectrum `.tap` is a block stream, a C64 `.tap` a pulse recording), so the
machine is always named and each machine is its own module,
`build198x::tape::<manufacturer>_<system>`, as
[`module-and-crate-naming.md`](module-and-crate-naming.md) names formats.

The first machine is the **ZX Spectrum** (`sinclair-zx-spectrum`), writing the
standard commercial cassette shape of 1983–84 as a `.tap`:

1. an auto-running **BASIC loader**,
2. a **SCREEN$ loading screen** (6912 bytes; `build198x image` emits the
   format, and a built-in test card stands in when there is no art), and
3. the **CODE block**, the program at its load address.

**The loader is generated by default.** It sets the colours, `CLEAR`s below the
CODE, loads the screen, silences ROM printing so "Bytes: name" does not land on
the screen, loads the CODE, restores printing and calls the entry. Because the
tool writes it, it can check every address: the screen size, the CODE fitting
the 16K or 48K model, the entry lying inside the CODE, and the CODE sitting high
enough for the loader to `CLEAR` and `LOAD` beneath it. That floor was measured
on the 48K ROM, not guessed.

**`--basic` replaces it with an authored loader**, used exactly as written, as
`plus3` does. The tool lints it and still checks the screen and CODE extent,
but the authored loader's `CLEAR` and `USR` belong to its author.

## The concrete need (the gate)

Per [`demand-gate-opening.md`](demand-gate-opening.md), each tool starts when
its own concrete need fires. The need is the curriculum's Spectrum game tapes.
**Meteor Storm** (Code198x Spectrum assembly, module 2) ships a loader + SCREEN$
+ CODE tape today, built by joining three separately framed files with `cat` in
its Makefile. That is the hand-rolled block composition this org exists to
replace. `build198x tape --basic` reproduces that tape byte for byte, and the
generated loader loads the same screen and game through the real ROM in Emu198x
and MAME.

Gloaming first opened this gate (2026-07-03). It is being removed from the
curriculum, so it is no longer the consumer.

Named future consumers, *not* opened by this record: TZX with turbo or custom
loaders, multiload, 128K paging, and other machines' tapes. Each fires its own
gate when real.

## Scope fence

In: Spectrum TAP composition through Format198x's TAP and BASIC crates, the
generated stock-ROM loader, authored loaders, SCREEN$ + CODE payloads, 48K and
16K models. Out until their own gates fire: TZX, turbo loaders, multiload, copy
protection, 128K, and other machines' tape formats.

## Settled ownership

The seam splits by composition
([`tape-framing-vs-mastering.md`](../../../decisions/tape-framing-vs-mastering.md)).
A tape whose content is the assembled program and nothing else, including the
pasmo `--tapbas`-parity stub, is an Asm198x *framing*. Once a second artifact
joins (a loading screen, an authored loader, another program), it is
*mastering*, owned here. The tape master ingests a raw binary and its load
address, with no dependency on Asm198x's tape serialiser. Byte layouts stay in
Format198x: the BASIC tokeniser
([`format198x-sinclair-zx-spectrum-bas`](https://crates.io/crates/format198x-sinclair-zx-spectrum-bas))
and the TAP codec
([`format198x-sinclair-zx-spectrum-tap`](https://crates.io/crates/format198x-sinclair-zx-spectrum-tap)).
